## Get started

```tsx
import { Button, KitProvider, TextField } from '@nisakhantalib/my-ui-kit';
import '@nisakhantalib/my-ui-kit/styles.css';

export function App() {
  return (
    <KitProvider locale="en-SG" currency="SGD">
      <TextField label="Payee name" />
      <Button>Continue</Button>
    </KitProvider>
  );
}
```

Set the brand and theme on `<html>` (`data-brand="orchid"`, `data-theme="dark"`); every component follows through the tokens. The toolbar above switches both for every story.

## Principles

1. **Native first.** A real `<button>`, `<select>` or radio beats a re-implementation. Phones, screen readers and browser autofill already know them.
2. **Accessible by default, not by option.** Labels, descriptions, error wiring and focus management are built in. You cannot render a `TextField` without a label.
3. **Composable over configurable.** `Tabs`, `RadioGroup` and `Accordion` are compound components, so layout stays in your hands instead of in a growing list of props.
4. **One contract for state.** Every stateful component works controlled (`value` + `onValueChange`) or uncontrolled (`defaultValue`).
5. **Tokens, not hard-coded values.** Colours, type and spacing come from the token files, so brands, themes, Tailwind and native shells stay in sync.

## Using this Storybook

- **Toolbar:** theme (light / dark), brand (Civic, Orchid, Private) and market (locale and currency). Every story must pass in all of them.
- **Accessibility panel:** axe-core WCAG 2.2 A/AA results for the current story, the same rules CI enforces.
- **Docs pages:** status, a live example, the props table and every variant, in the same order for each component.
